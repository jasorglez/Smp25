CONFIGURAR AVISOS DE COBRANZA POR RABBITMQ EN LINUX

Los cambios de código requieren desplegar el frontend y el servicio Telegram.
No ejecutes los comandos con una contraseña inventada: usa una contraseña
aleatoria y guárdala en el gestor de secretos del servidor.

1) Crear un virtual host y un usuario dedicados en el servidor RabbitMQ:

  sudo rabbitmqctl add_vhost /biapp-cobranza
  read -s RABBIT_PASSWORD
  sudo rabbitmqctl add_user biapp_cobranza "$RABBIT_PASSWORD"
  unset RABBIT_PASSWORD
  sudo rabbitmqctl set_permissions -p /biapp-cobranza biapp_cobranza '.*' '.*' '.*'

El usuario queda limitado al virtual host /biapp-cobranza. No abras el puerto
15672 a Internet; el servicio Telegram se conecta al puerto AMQP 5672.

2) Configurar los secretos para el despliegue automatizado.

Tu script telegram.sh hace git pull y luego docker compose down/build/up en
/bi/repos/ChatbotFresh/chatBotTelegram. El docker-compose.yml del repositorio
ya está preparado para leer las variables de un archivo local .env; no tienes
que editar docker-compose.yml en el servidor. Ese .env está excluido de Git.

Crea o edita el archivo exacto:

  sudo nano /bi/repos/ChatbotFresh/chatBotTelegram/.env

Escribe estas líneas, reemplazando los valores señalados por la contraseña
que asignaste al usuario RabbitMQ y por el valor Key de Security, sin comillas:

  RabbitMq__Enabled=true
  RabbitMq__HostName=host.docker.internal
  RabbitMq__Port=5672
  RabbitMq__UserName=biapp_cobranza
  RabbitMq__Password=REEMPLAZA_POR_LA_CONTRASENA_QUE_CREASTE
  RabbitMq__VirtualHost=/biapp-cobranza
  Jwt__Key=REEMPLAZA_POR_EL_VALOR_DE_Jwt_Key_DE_SECURITY

RabbitMQ y Telegram corren en bi-server. host.docker.internal permite al
contenedor llegar al RabbitMQ del servidor sin usar la IP pública. Guarda en
nano con Ctrl+O, Enter, Ctrl+X. Como telegram.sh corre como jsoriano, asigna
el archivo a ese usuario y protege los secretos:

  sudo chown jsoriano:jsoriano /bi/repos/ChatbotFresh/chatBotTelegram/.env
  sudo chmod 600 /bi/repos/ChatbotFresh/chatBotTelegram/.env

No guardes .env en Git ni pegues sus valores en un chat. Jwt__Key debe ser
exactamente el valor Jwt:Key de Security.

3) Ejecuta tu automatización telegram.sh. Ella hará git pull y reconstruirá el
contenedor. No uses systemctl ni hace falta reiniciarlo a mano.

4) Comprobar los logs y la conexión:

  sudo docker logs --tail 100 chatbot-telegram

El log debe dejar de decir "Consumidor RabbitMQ de Cobranza desactivado" y
mostrar que escucha su cola. Comprueba también RabbitMQ:

  sudo rabbitmqctl list_connections user vhost state
  sudo rabbitmqctl list_queues -p /biapp-cobranza name messages consumers

El servicio Telegram declara automáticamente el exchange y la cola durable al
iniciar. La interfaz se conecta a /telegram/cobranzaHub y muestra el aviso solo
a usuarios autenticados que tengan permiso activo en la empresa seleccionada.
