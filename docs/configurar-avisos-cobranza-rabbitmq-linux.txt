CONFIGURAR AVISOS DE COBRANZA POR RABBITMQ EN LINUX

Los cambios de código requieren desplegar el frontend y el servicio Telegram.
No ejecutes los comandos con una contraseña inventada: usa una contraseña
aleatoria y guárdala en el gestor de secretos del servidor.

1) Crear un virtual host y un usuario dedicados en el servidor RabbitMQ:

  sudo rabbitmqctl add_vhost /biapp-cobranza
  read -s RABBIT_PASSWORD
  sudo rabbitmqctl add_user biapp_cobranza "$RABBIT_PASSWORD"
  unset RABBIT_PASSWORD
  sudo rabbitmqctl set_permissions -p /biapp-cobranza biapp_cobranza '.*' '.*' '.*'

El usuario queda limitado al virtual host /biapp-cobranza. No abras el puerto
15672 a Internet; el servicio Telegram se conecta al puerto AMQP 5672.

2) Configurar las variables en el contenedor Docker de Telegram.

Los logs que compartiste indican que RabbitMQ está desactivado dentro del
contenedor. Para localizar la carpeta del docker-compose en el servidor donde
corre Telegram:

  COMPOSE_DIR=$(sudo docker inspect --format='{{ index .Config.Labels "com.docker.compose.project.working_dir" }}' chatbot-telegram)
  echo "$COMPOSE_DIR"
  cd "$COMPOSE_DIR"

Edita el docker-compose.yml de esa carpeta:

  sudo nano docker-compose.yml

Dentro del servicio api, agrega al mismo nivel que environment: esta sección:

  env_file:
    - .env

Crea el archivo de secretos:

  sudo nano .env

Escribe estas líneas. Usa la IP de bi-server que compartiste para RabbitMQ y
reemplaza los dos valores indicados por tus secretos reales, sin comillas:

  RabbitMq__Enabled=true
  RabbitMq__HostName=66.179.240.10
  RabbitMq__Port=5672
  RabbitMq__UserName=biapp_cobranza
  RabbitMq__Password=REEMPLAZA_POR_LA_CONTRASENA_QUE_CREASTE
  RabbitMq__VirtualHost=/biapp-cobranza
  Jwt__Key=REEMPLAZA_POR_EL_VALOR_DE_Jwt_Key_DE_SECURITY

Guarda el archivo en nano con Ctrl+O, Enter, Ctrl+X. Protege los secretos y
recrea el contenedor para que Docker los cargue:

  sudo chmod 600 .env
  sudo docker compose up -d --force-recreate api

No guardes .env en Git ni pegues sus valores en un chat. Jwt__Key debe ser
exactamente el valor Jwt:Key del appsettings.json activo de Security.

3) Reiniciar Telegram y comprobar logs/conexiones:

Si solo vas a reiniciar el contenedor con la configuración que ya tiene:

  sudo docker restart chatbot-telegram

Ver los últimos logs del contenedor:

  sudo docker logs --tail 100 chatbot-telegram

IMPORTANTE: docker restart NO carga cambios nuevos de variables de entorno.
Si cambiaste RabbitMq__* o Jwt__Key, recrea el contenedor como se indicó arriba;
docker restart por sí solo no carga variables de entorno nuevas. El servicio
Compose se llama api.

  COMPOSE_DIR=$(sudo docker inspect --format='{{ index .Config.Labels "com.docker.compose.project.working_dir" }}' chatbot-telegram)
  cd "$COMPOSE_DIR"
  sudo docker compose up -d --force-recreate api

Después comprueba RabbitMQ (estos dos comandos se ejecutan en bi-server):

  sudo rabbitmqctl list_connections user vhost state
  sudo rabbitmqctl list_queues -p /biapp-cobranza name messages consumers

El servicio Telegram declara automáticamente el exchange y la cola durable al
iniciar. La interfaz se conecta a /telegram/cobranzaHub y muestra el aviso solo
a usuarios autenticados que tengan permiso activo en la empresa seleccionada.
